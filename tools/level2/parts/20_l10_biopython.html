Lesson 10Biopython, going further

🧬 Why this matters in bioinformatics

A FASTA file gives you a sequence and a name. A GenBank file gives you the whole story: which organism, which publication, and where the interesting parts are, such as the coding sequence, the exons and the poly-A signal. Reading these annotations, and translating sequences correctly, are everyday tasks. And when a sequence hasn't been annotated yet, you need to find its genes yourself, in all six reading frames.

Features: where things are

  
Each entry in the FEATURES table becomes a feature object with a .type (such as gene, exon or CDS), a .location, and a dictionary of extra details called .qualifiers.




  

    ⚠️ Two ways of counting, again
    
The GenBank file says the CDS is at 51..494: biology numbering, from 1, and including both ends. Biopython shows [50:494]: a Python slice, from 0, with the end excluded. They describe exactly the same bases! To convert, subtract 1 from the start only. The (+) means the feature is on the forward strand; (-) would mean the reverse strand.

  


  
The CDS feature is the most interesting one: it's the coding sequence, the part that becomes protein. feature.extract(record.seq) cuts its sequence out for you (and, for features on the reverse strand, reverse-complements it too):




  
Each qualifier is a list, because GenBank allows a qualifier to appear more than once. That's why we write [0] to get the first (here, only) value.


  
Translating with the right genetic code

  
Biopython's .translate() has two options worth knowing. cds=True says "this is a complete coding sequence": Biopython then checks that it starts with a start codon, ends with a stop codon, has no stop codons in the middle and is a whole number of codons long, and raises an error if not. It's a free quality check! Let's compare our translation with the one NCBI wrote in the file:




  
The second option is table=, the translation table. Level 1 told you that some organisms use slightly different genetic codes. Mitochondria are the famous example: in human mitochondria, TGA means tryptophan (W) instead of "stop", and AGA means "stop" instead of arginine (R). NCBI numbers its genetic codes: table 1 is the standard code, table 2 is the vertebrate mitochondrial code.




  
Same DNA, different proteins! If you translate a mitochondrial gene with the standard table, you get a protein full of false stops. GenBank records tell you which table to use: look for a /transl_table= qualifier on the CDS (when it's missing, the standard table 1 applies).

  

    🤓 Did you know?
    
NCBI lists more than 25 genetic codes. Some ciliates (single-celled pond organisms) read TAA and TAG as glutamine, and a few bacteria use the stop codon TGA to insert a 21st amino acid, selenocysteine. The "universal" genetic code is almost universal.

  


  
Six-frame translation

  
When you receive a new sequence with no annotation, you don't know where its gene is, or even which strand it's on. Each strand can be read in 3 reading frames (starting at base 1, 2 or 3), and there are 2 strands, so there are six frames to check. For the reverse strand, translate the reverse complement.

  
One detail: Biopython warns you when a sequence isn't a whole number of codons long. To keep things tidy, we trim each frame to a multiple of 3 first, using // from Level 1.




  
Look at frame +3: …QTDTMVHLTPEEKS…. There's beta-globin, starting at the M! The coding sequence starts at base 51, and 51 is in frame 3 (frame 1 holds bases 1, 4, 7, …, 49, 52; frame 3 holds 3, 6, …, 48, 51). The other frames are full of * stop codons, which is typical: random sequence hits a stop codon about every 21 codons (3 of the 64 codons are stops).


  
🧪 Project: find the longest ORF

  
A simple way to guess where a gene is: find the longest open reading frame in all six frames. In each translated frame, the stretches between stop codons are separated by *, so .split("*") gives them as a list. In each stretch, an ORF starts at the first M:




  
147 amino acids in frame +3: exactly the beta-globin protein that NCBI annotated. Without reading the annotation at all, a few lines of code found the gene. 🎉 (Real gene finders are smarter: they model splicing, codon usage and more. But "longest ORF" is a surprisingly good first guess for an mRNA.)

  
Notice best_frame, best_protein = None, "": you can set two variables in one line. A function can also return two values at once, as longest_orf does; they come back as a pair (a tuple), which you can unpack straight into two variables.

  

    ⚠️ An ORF that runs off the end
    
If a stretch has no * after it, the ORF runs off the end of the sequence without a stop codon. It might be a real gene that's cut off, or just chance. Our simple function counts it anyway; careful tools report it separately.

    ✅ Key takeaways
    
    
      
  • A SeqRecord is a Seq plus its ID, description, annotations and features.
    • 
      
  • SeqIO.read(file, "genbank") reads a GenBank record; record.features lists its features, each with .type, .location and .qualifiers.
    • 
      
  • GenBank 51..494 = Python [50:494]. feature.extract(record.seq) cuts a feature's sequence out.
    • 
      
  • .translate(cds=True) checks a complete CDS; table= picks the genetic code (1 = standard, 2 = vertebrate mitochondrial).
    • 
      
  • Six frames = 3 per strand. The longest ORF is a good first guess for where a gene is.
