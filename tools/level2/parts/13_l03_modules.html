Lesson 3Modules and imports

🧬 Why this matters in bioinformatics

Every function you don't have to write is a function you don't have to test and debug. Python comes with hundreds of ready-made modules for maths, statistics, counting, randomness, files and the internet. Knowing what's already there saves hours, and the built-in tools are well tested. In this lesson you'll use them to count k-mers, the short "words" that genome assemblers and many modern tools are built on.

🧪 Project: counting k-mers

A k-mer is a piece of sequence k bases long. To list all k-mers, slide a window of width k along the sequence one base at a time. Unlike codons, k-mers overlap:

GATTACA      all 3-mers, sliding one base at a time:
GAT          position 1
 ATT         position 2
  TTA        position 3
   TAC       position 4
    ACA      position 5      →  7 bases − 3 + 1 = 5 k-mers

🤓 Did you know?

k-mers power a lot of modern bioinformatics. Genome assemblers stitch reads together through shared k-mers. Tools such as Kraken identify which species a read came from by looking up its k-mers, and k-mer counts from raw reads can even estimate a genome's size before it has been assembled.

random: simulations you can repeat

Random numbers are useful for simulating data, for example to test a pipeline or to ask "would I see this pattern by chance?". random.choice() picks a random item, and random.random() gives a decimal between 0 and 1. One new trick here: "".join(list_of_strings) glues a list of strings into one string.

Run it a few times: you get the same "random" sequence every time, because of random.seed(42). Now delete the seed line and run again: the result changes on every run. (The _ in for _ in range(30) is a name that means "I don't need this value, I just want to repeat 30 times".)

🧹 Good habit: set a random seed

Computer "randomness" comes from a starting number, the seed. Setting it yourself makes your analysis reproducible: anyone who runs your code gets exactly the same numbers you did, including you next year. Write the seed as a named constant at the top of the script, and mention it in your methods.

Writing your own module

Here's the nice part: any .py file is a module. If you save your best functions in a file called seqtools.py, every script in the same folder can import seqtools. This page already has one in its folder, with the Level 1 toolkit inside:

🌶️ Challenge 3.4✍️ Write itSimulate sequencing errors, reproducibly

    
Complete add_errors(seq, error_rate, seed=1). It should set the random seed, then go through seq base by base. With probability error_rate, replace the base with a different base chosen at random from A, C, G and T; otherwise keep it. Return the new sequence. Calling it twice with the same seed must give the same answer.


    

      
Start with random.seed(seed), and build the result in a list, new_bases = [].

      
For each base: if random.random() < error_rate: pick a replacement with random.choice([b for b in "ACGT" if b != base]), otherwise keep base.

      
At the end: return "".join(new_bases).

    



  


  

    
Quick quiz

    

      
1. After import statistics as stats, how do you call median?

      
    
        
  • Right: the module is now known by its nickname, stats.
    • 
        
  • That needs from statistics import median. With "import ... as", you use the nickname and a dot.
    • 
        
  • With "as stats", the name statistics isn't defined in your code, only stats.
    • 
      

    

    

      
2. How many 3-mers does a 10-base sequence contain?

      
    
        
  • That's the number of complete codons (non-overlapping). k-mers overlap.
    • 
        
  • Yes: length − k + 1 = 10 − 3 + 1 = 8.
    • 
        
  • The last two positions don't have room for a full 3-mer.
    • 
      

    

    

      
3. Why call random.seed(42) at the start of a simulation?

      
    
        
  • It doesn't make them more random; it makes them repeatable.
    • 
        
  • Exactly. That makes your analysis reproducible by others and by future you.
    • 
        
  • They work without a seed, but give different results on every run.
    • 
      

    

    

      
4. You have a file seqtools.py with a function gc_content. How can another script in the same folder use it?

      
    
        
  • That works, but now there are two copies to keep in sync. Importing is the better way.
    • 
        
  • Yes. Any .py file in the same folder can be imported as a module (without the .py).
    • 
        
  • Leave out the .py: the module's name is just seqtools.
