🧬 Why this matters in bioinformatics

Code is read far more often than it's written: by your colleagues, by reviewers checking a paper, and by future you, six months from now, wondering what x2 meant. In science, clean code isn't about looking smart. It's about making mistakes easy to spot, so the results can be trusted.

Meaningful names

Good names say what a value is (sequences, min_length, gc_percent) and good function names say what the function does (keep_long_sequences, read_fasta). Single letters are fine only for tiny, obvious things, such as i for a position in a short loop.

Better docstrings

In Level 1 you wrote one-line docstrings. For functions other people will use, a slightly longer docstring is a gift: say what goes in, what comes out, and give a tiny example. Python's help() shows a function's docstring, so it doubles as a mini manual:

Default arguments

A default argument is a parameter with a ready-made value. If the caller doesn't give one, the default is used. You've already met one without knowing it: in Biopython's translate(to_stop=True), to_stop is a parameter whose default is False.

Writing as_percent=False in the call, with the parameter's name, is called a keyword argument. It makes calls easy to read: gc_content(seq, False) works too, but what does False mean there? Use simple values for defaults: numbers, text, True/False or None.

No "magic numbers": name your thresholds

A magic number is an unexplained number in the middle of your code, like if len(seq) > 100:. Why 100? Is it the same 100 as on line 80? Give it a name in capitals at the top of your script (you met this convention with CODON_TABLE in Level 1). Capitals mean "a constant: set once, never changed":

Now, if your supervisor says "let's use 150 bases", you change one line, and the reason is written right next to it. (Bonus: :.0% in an f-string shows a fraction as a percentage.)

PEP 8: Python's style guide

Python has an official style guide called PEP 8. You don't need to memorise it. Most of it is common sense, and you're already following much of it. The main points:

🤓 Did you know?

PEP stands for "Python Enhancement Proposal". PEP 8 was written in 2001, partly by Python's creator, Guido van Rossum. Its key idea: "code is read much more often than it is written". Tools called formatters (such as Black or Ruff) can tidy your code into PEP 8 style automatically.

  • The speed is the same. The benefit is for humans.

✅ Key takeaways
  • x += 1 is short for x = x + 1; enumerate(seq, start=1) gives each item with its position.
  • List comprehension: [expression for item in things if condition]. Dictionary comprehension: {key: value for item in things}.
  • Use clear names, docstrings that say what goes in and comes out, and default arguments for optional settings.
  • Name your thresholds (MIN_LENGTH = 100) instead of hiding magic numbers in the code.
  • PEP 8 is Python's style guide: lowercase_with_underscores, CAPITALS for constants, 4-space indents.
