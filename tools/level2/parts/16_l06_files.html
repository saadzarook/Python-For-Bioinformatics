Lesson 6Reading and writing files properly

🧬 Why this matters in bioinformatics

Results that only live on your screen disappear when you close the window. Real analyses save their results to files: filtered sequences for the next tool, tables for colleagues, spreadsheets for supervisors. And the original data, the raw reads that cost money and time to produce, must never be changed. In this lesson you'll write files safely and in the formats everyone else can open.

Writing a text file

In Level 1 you opened files for reading with with open(filename) as f:. To write, add a second argument, the mode, "w". Then f.write(text) puts text into the file. Unlike print(), .write() doesn't add a new line for you, so add "\n" yourself at the end of each line.

As before, with closes the file automatically when the indented block ends. That matters even more for writing: text is only guaranteed to be saved once the file is closed.

ModeMeaningIf the file already exists…
"r"read (the default)it's read; nothing changes
"w"write⚠️ it's emptied first, with no warning
"a"appendnew text is added at the end
"x"createyou get an error instead: a safe way to never overwrite anything
⚠️ Never modify raw data

Mode "w" empties the file the moment it opens, even if you then write nothing. Open your raw data (FASTQ, FASTA, the files that came from the sequencer or database) for reading only, and always write results to new files with new names. If something goes wrong, you can simply delete the results and run your code again from the untouched raw data.

On this page, the original data files are put back before every run, so you can't permanently damage them here. On your own computer there's no such safety net!

🤓 Did you know?

Spreadsheet programs have a habit of "helpfully" changing data. Open a gene list in Excel, and genes such as SEPT2 and MARCH1 become the dates 2-Sep and 1-Mar. A 2016 study found this error in about a fifth of published papers that shared gene lists as Excel files. In 2020, the committee that names human genes gave up and renamed them: SEPT2 is now SEPTIN2 and MARCH1 is MARCHF1. The lesson: keep raw data untouched, and do your processing in code.

🧹 Good habit: read back what you write

After writing a results file, read it back and check a few things: the number of records, the lengths, the first lines. It takes one minute and catches whole families of bugs, such as a missing "\n" that glues all your sequences together.

Tables: CSV and TSV files

Most results are tables. The two most common plain-text table formats are CSV (comma-separated values) and TSV (tab-separated values). Every program can open them: Excel, R, pandas (next lesson), and your colleagues' tools. You could write them with f.write(), but values that contain commas or quotes make that surprisingly tricky. Python's csv module handles all of it.

Two details: writer.writerow() takes a list, one item per column, and newline="" in open() lets the csv module control line endings, which avoids blank lines between rows on Windows. round(x, 1) rounds a number to 1 decimal place.

Reading works the same way. csv.DictReader is especially nice: it uses the header row so you can get each value by its column name. For a TSV file, tell it the separator is a tab, delimiter="\t". Here's this page's gene annotation table (made-up teaching data, used again in Lesson 8):

⚠️ Everything read from a file is text

The csv module gives you strings, even for numbers: row["chromosome"] is "17", not 17. Convert with int() or float() before doing maths. (Remember the "30" vs 30 warning from Level 1? Here it is in real life.) In the next lesson, pandas will do these conversions for you.

Quick quiz

1. You open an existing results file with open("results.csv", "w"). What happens to its old contents?

  • That's mode "a" (append).
  • Right. That's why you never open raw data with "w".
  • It doesn't ask. Mode "x" is the safe one: it refuses to open a file that already exists.

2. Why does f.write(seq) often need + "\n"?

  • Exactly. print() adds a new line for you; .write() writes only what you give it.
  • The with block closes the file. "\n" is the new-line character.
  • "\n" isn't written as a backslash: it's the invisible new-line character.

3. You read a TSV file with csv.DictReader(f, delimiter="\t"). What type is row["length"]?

  • The csv module doesn't guess types: everything comes in as text.
  • Yes. Convert it with int(row["length"]) before doing maths.
  • The whole row is a dictionary; each value in it is a string.
✅ Key takeaways
  • with open(name, "w") as f: writes a file; "a" appends; "w" erases an existing file first.
  • .write() doesn't add new lines: include "\n" yourself.
  • Never modify raw data. Read it, and write results to new files.
  • Use the csv module for tables: csv.writer and writerow() to write, csv.DictReader to read; delimiter="\t" for TSV.
  • Read back what you wrote, and remember that values read from files are text.
