Lesson 5FASTQ files and quality scores

🧬 Why this matters in bioinformatics

A modern sequencing machine reads millions of short DNA fragments in one run, and it isn't equally sure about every base it reports. Along with each base it gives a quality score: how confident it is that the base is right. Almost every sequencing analysis starts with quality control (QC): throwing away bad reads and trimming bad ends. Skip this step, and sequencing errors can look like mutations. In bioinformatics, "garbage in, garbage out" is very real.

What is a sequencing read?

To sequence DNA, it's first broken into many short fragments. The machine then reads the bases of each fragment, one chemical cycle at a time. Each piece of sequence it reports is called a read. On the most common machines (made by Illumina), reads are usually 50 to 300 bases long, and one run can produce hundreds of millions of them.

Quality usually drops towards the end of a read, the 3′ end. Imagine thousands of copies of the same fragment being read together, in a cluster. With every cycle, a few copies fall a step behind or jump a step ahead, so the signal gets blurrier and the machine becomes less sure. That's why trimming the 3′ end of reads is so common.

The FASTQ format

FASTQ is the standard file format for reads. It's like FASTA with quality scores added. Every read takes exactly four lines:

LineStarts withContains
1@the read's ID (first word) and an optional description
2the sequence
3+a separator (sometimes the ID is repeated after it)
4the quality string: one character per base, so it's exactly as long as the sequence

It's made-up teaching data: the sequences are real pieces of the HBB, INS, TP53 and GAPDH genes, and the quality scores were simulated to behave like real Illumina reads, with quality falling towards the 3′ end and a few poor reads.

Those funny symbols on every fourth line are the quality scores. Let's decode them.


  
Phred quality scores

  
Each quality is a Phred score, Q. It's based on the probability P that the base is wrong, on a log10 scale (remember math.log10() from Lesson 3?):

  
Q = −10 × log10(P),   so   P = 10−Q/10

  

    

      
Phred score QChance the base is wrongAccuracy

      
        
101 in 1090%

        
201 in 10099%

        
301 in 1,00099.9%

        
401 in 10,00099.99%

      
    

  

  
Every 10 points means 10 times fewer errors. Q30 is a common benchmark for "good" data, and Q20 is a common minimum.




  
From characters to numbers: Phred+33

  
To store each score as a single character, FASTQ uses the ASCII code: every character has a number (A is 65, ! is 33). Python's ord() gives a character's number and chr() goes the other way. In the Phred+33 encoding used by all modern machines:

  
Q = ord(character) − 33




  

    🤓 Did you know?
    
Why 33? The first 32 ASCII codes are invisible "control" characters, and number 32 is a space. So !, number 33, is the first visible character, and it stands for Q0. Some older Illumina machines used Phred+64 instead, so the same quality string meant different scores. If your qualities ever come out impossibly high (like Q70), that's a big clue. The name "Phred" comes from a base-calling program written in the 1990s for the Human Genome Project.

Trimming the 3′ end, with a while loop

  
A read can be excellent for 30 bases and poor for the last 10. Rather than throw it all away, we can trim the poor end. The idea: start at the end, and step backwards while the quality is below the threshold.

  
This needs a new kind of loop. A for loop repeats once for each item. A while loop repeats as long as a condition is True, checking it again before every round:




  
The loop removes 8, 11 and 14, then stops at 22, which is good enough. The 19 before it stays: we only trim the poor end, because cutting a hole in the middle of a read would join bases that aren't next to each other. The end > 0 part stops the loop if the whole read is poor.

  

    ⚠️ Make sure a while loop can stop
    
If the condition never becomes False, a while loop runs forever. Here, end gets smaller every round, so it must eventually stop. Always check that something inside the loop moves it towards the end.

  


  
FASTQ with Biopython

  
Biopython reads FASTQ just like FASTA: change the format name to "fastq". Each record has a .letter_annotations["phred_quality"] list, already decoded. Best of all, when you slice a record, the qualities are sliced with it. (The first time you run this, the page downloads Biopython, which takes a few seconds.)




  

    🧹 Good habit: check your code against a trusted tool
    
Run the hand-written mean_quality() and Biopython side by side on the same file: they should agree exactly. If they don't, one of them (probably yours!) has a bug. In real projects, tools such as FastQC produce full quality reports, and you'll make your own version in the capstone.

Quick quiz

    

      
1. How many lines does one read take in a FASTQ file?

      
    
        
  • FASTA has a header and sequence lines. FASTQ adds a + line and a quality line.
    • 
        
  • Right: @header, sequence, + separator, quality string.
    • 
        
  • In FASTQ files from sequencers, it's always 4 lines per read, however long the read.
    • 
      

    

    

      
2. A base has quality Q30. What does that mean?

      
    
        
  • Phred is a log scale, not a percentage.
    • 
        
  • Correct: P = 10^(−30/10) = 0.001, so 99.9% accuracy.
    • 
        
  • The quality score says how sure the machine is, not where the base is.
    • 
      

    

    

      
3. In Phred+33, which character means Q40?

      
    
        
  • You need to add the offset: 40 + 33 = 73.
    • 
        
  • Yes: chr(40 + 33) is "I".
    • 
        
  • "!" means Q0, the lowest possible score.
    • 
      

    

    

      
4. Why does quality usually drop towards the 3′ end of a read?

      
    
        
  • Exactly. The later the cycle, the less certain the machine is.
    • 
        
  • It's about the sequencing process, not the DNA itself.
    • 
        
  • It's not a choice: errors simply build up cycle after cycle.
    • 
      

    

  


  

    ✅ Key takeaways
    
    
      
  • A FASTQ record is 4 lines: @ID, sequence, +, and a quality string of the same length.
    • 
      
  • Phred score: Q = −10 × log10(P). Q20 = 1 error in 100, Q30 = 1 in 1000.
    • 
      
  • Phred+33: Q = ord(character) - 33.
    • 
      
  • Basic QC: filter reads by mean quality and trim poor 3′ ends. A while loop repeats while a condition is True.
    • 
      
  • SeqIO.parse(file, "fastq") gives records with letter_annotations["phred_quality"]; slicing a record keeps its qualities.
