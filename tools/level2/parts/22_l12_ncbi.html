Lesson 12Getting data from NCBI

🧬 Why this matters in bioinformatics

Clicking through a website to download one sequence is fine. Downloading 500 sequences that way is a long, error-prone afternoon, and nobody can repeat exactly what you did. With a few lines of code, you can search NCBI and download records automatically, and your script becomes a precise record of where your data came from. That's reproducibility again, this time for data collection.

NCBI and accession numbers

You met NCBI in Level 1: the US National Center for Biotechnology Information, which runs some of the world's biggest free biology databases, including Nucleotide (DNA and RNA sequences), Protein, Gene and PubMed (scientific papers). Every record has an accession number, and its first letters tell you what kind of record it is:

PrefixKind of recordExample
NM_mRNA, curated by NCBI (RefSeq)NM_000518.5 (human HBB mRNA)
NP_protein, curated (RefSeq)NP_000509.1 (beta-globin protein)
NC_a complete chromosome or genomeNC_000011.10 (human chromosome 11)
XM_ / XP_mRNA / protein predicted by computer, not yet curated

The number after the dot is the version. When NCBI corrects a sequence, the version goes up (NM_000518.4 became NM_000518.5 in 2018). Always record the full accession with its version, so you know exactly which sequence you used.

E-utilities: NCBI's question-and-answer service

NCBI's E-utilities are web addresses that answer questions from programs instead of people. They're an API: a way for programs to talk to each other. The two you'll use most:

  • esearch: "Which records match this search?" It gives back a list of record IDs.
  • efetch: "Send me these records." It gives back the records themselves, for example as FASTA or GenBank text.

Your question is written into the web address itself. Everything after the ? is a list of name=value settings joined by &. Spaces and brackets aren't allowed in web addresses, so they're encoded (a space becomes +, [ becomes %5B). urlencode() from the standard library builds this for you from a dictionary:

The search term uses NCBI's search syntax: [gene], [orgn] and [filter] say which field each word should match. refseq_select asks for NCBI's one recommended transcript per gene. You can paste that address into your browser's address bar and see the answer yourself!

Being a polite user

🧹 Good habit: NCBI's rules for scripts
  • No more than 3 requests per second. NCBI's servers are shared by the whole world. Scripts that hammer them get blocked. With a free API key you may make up to 10 per second.
  • Say who you are. Send a tool name and an email address with your requests, so NCBI can contact you if your script causes problems instead of just blocking it.
  • Use your own email, and never someone else's. And never put your email or API key in code that you share or publish: keep the key in a setting on your own computer (see below).
  • Big downloads (more than about 100 requests) belong on weekends or between 9 pm and 5 am US Eastern time.
  • Download once, save the file, and work from your copy. Don't download the same record again every time your script runs.

The Biopython way (on your own computer)

On your own computer, Biopython's Entrez module talks to the E-utilities for you: it builds the addresses, sends your email and API key, and even waits between requests to respect the rate limit. Here's what it looks like. This box isn't runnable on this page, because Biopython's Entrez uses a networking tool that doesn't work inside a web browser:

💻 Run this on your own computernot runnable here
import os
from Bio import Entrez, SeqIO

Entrez.email = "your.name@example.org"           # ← put YOUR OWN email address here
Entrez.api_key = os.environ.get("NCBI_API_KEY")  # optional: read from a setting, never typed in the code

# 1. Search: which records match?
handle = Entrez.esearch(db="nucleotide",
                        term="HBB[gene] AND Homo sapiens[orgn] AND refseq_select[filter]")
result = Entrez.read(handle)
handle.close()
print("Found:", result["Count"], "record(s), IDs:", result["IdList"])

# 2. Fetch: download a record as FASTA, and save it to a file
handle = Entrez.efetch(db="nucleotide", id="NM_000518.5", rettype="fasta", retmode="text")
text = handle.read()
handle.close()
with open("NM_000518.5.fasta", "w") as f:
    f.write(text)

record = SeqIO.read("NM_000518.5.fasta", "fasta")
print(record.id, len(record.seq), "bases")

os.environ.get("NCBI_API_KEY") reads an "environment variable", a setting stored on your computer rather than in your code. That way you can share your script without sharing your key.

The browser way (runnable here)

Inside a web browser, Python has to ask the browser to download things. Pyodide gives us pyfetch() for that. Browsers also only let a page fetch data from another website if that website allows it; NCBI's E-utilities do. We've put a small helper, fetch_text(), in this page's folder as ncbi_helper.py. It waits politely between requests, and if NCBI can't be reached (no internet, a network that blocks it, or too many requests), it falls back to a saved copy of NCBI's answer that comes with the page:

ncbi_helper.py


  
One new word: await. Downloading takes time, and a web page must never freeze while it waits. await means "pause this code here until the answer arrives, and let the page carry on meanwhile". You only need it in the browser version; the Biopython code above waits without it.




  
The answer comes as JSON, a text format made of nested dictionaries and lists. json.loads() turns it into real Python dictionaries and lists. The ID is a plain number, NCBI's internal "UID" for the record. efetch accepts either that number or an accession; accessions are easier for humans, so let's fetch by accession:

    💡 Saved copies are a good idea anyway
    
Databases change: records get new versions, search results grow. For a reproducible analysis, save what you downloaded (with the date) and run your analysis on that saved copy. That's exactly what the fallback files on this page are: esearch_hbb.json and efetch_hbb.fasta, saved from NCBI on 3 October 2026. The exercises below use them, so they work even offline.

    ✅ Key takeaways
    
    
      
  • Accession prefixes tell you the record type (NM_ mRNA, NP_ protein, NC_ chromosome); always record the version.
    • 
      
  • E-utilities answer questions sent as web addresses: esearch finds IDs, efetch downloads records. urlencode() builds the address.
    • 
      
  • Be polite: at most 3 requests per second (10 with an API key), send a tool name and your own email, and never share your key.
    • 
      
  • On your own computer, use Bio.Entrez. In the browser, this page uses pyfetch with await, with a saved copy as a fallback.
    • 
      
  • Save what you download, and analyse your saved copy.
